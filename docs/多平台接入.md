## 🔀 多平台接入建议

当前版本的推荐方式是：**一个平台对应一个 Bot 实例，各实例独立运行。**

这样设计的原因是，框架内部的 `IConnector`、`IDispatcher`、`IContactsManager`、`IMessageApi` 都以单实例模式组织。对于 OneBot、Discord、QQ 等不同平台，分别创建独立 Bot 实例可以避免以下问题：

*   平台连接状态互相影响，例如某个平台掉线导致整个运行时异常。
*   联系人缓存、异步会话、消息上下文混用，增加排查复杂度。
*   平台专属插件共用一条执行链时，出现上下文类型不匹配。

因此，如果你需要“多平台消息收发且彼此独立”，推荐采用以下思路：

*   **业务复用放在插件或服务层**：通用逻辑尽量写成跨平台插件。
*   **平台隔离放在 Bot 实例层**：每个平台单独创建 `BotBuilder` 并运行。
*   **部署方式按需求选择**：可以同进程启动多个 Bot，也可以拆成多个进程分别部署。

### 同进程多实例示例

适用于希望统一启动入口，但仍保持各平台运行时隔离的场景。

```cs
using MilkiBotFramework;
using MilkiBotFramework.Platforms.Discord;
using MilkiBotFramework.Platforms.GoCqHttp;

var oneBot = new BotBuilder()
    .UseGoCqHttp(GoCqConnection.WebSocket("ws://127.0.0.1:6700"))
    .Build();

var discordBot = new BotBuilder()
    .UseDiscord()
    .Build();

await Task.WhenAll(
    oneBot.RunAsync(),
    discordBot.RunAsync());
```

这种方式下：

*   两个平台各自拥有独立的连接器、分发器、联系人管理器和内部事件总线。
*   一个实例的重连、异常、缓存状态不会直接污染另一个实例。
*   若插件是通用插件，可以被两个实例分别加载并独立执行。

### 物理隔离示例

如果你更关注稳定性、灰度发布、独立重启和监控，建议直接拆成多个进程或服务。

例如：

*   `MyBot.OneBot`：只负责 OneBot 接入。
*   `MyBot.Discord`：只负责 Discord 接入。
*   `MyBot.Shared`：存放公共插件、公共服务和共享配置模型。

目录结构可以是：

```text
src/
  MyBot.Shared/
  MyBot.OneBot/
  MyBot.Discord/
```

其中 `MyBot.OneBot/Program.cs`：

```cs
using MilkiBotFramework;
using MilkiBotFramework.Platforms.GoCqHttp;

return await new BotBuilder()
    .UseGoCqHttp(GoCqConnection.WebSocket("ws://127.0.0.1:6700"))
    .Build()
    .RunAsync();
```

`MyBot.Discord/Program.cs`：

```cs
using MilkiBotFramework;
using MilkiBotFramework.Platforms.Discord;

return await new BotBuilder()
    .UseDiscord()
    .Build()
    .RunAsync();
```

### 插件编写建议

在多平台独立实例模式下，建议将插件分成两类：

*   **通用插件**：继承 `BasicPlugin`，只依赖 `MessageContext` 的通用字段。
*   **平台专属插件**：继承 `BasicPlugin<TContext>`，例如 `BasicPlugin<GoCqMessageContext>` 或 `BasicPlugin<DiscordMessageContext>`。

这样既可以最大化复用业务逻辑，也能在需要读取平台原始消息对象时保持类型安全。
